# 四、实现原理

## 4.1 发布流程（核心业务链路）

```
用户操作
  │
  ▼
前端：选择视频/图集 → 配置各平台参数 → 点击发布
  │
  ▼
前端：POST /api/v2/publish （携带所有配置）
  │
  ▼
后端 ext_api/__init__.py：
  1. 创建 publish_batches 记录（状态: pending）
  2. 为每个目标账号创建 publish_details 记录
  3. 将任务加入 TaskQueue（asyncio.Queue）
  4. 立即返回 batch_id，前端轮询 SSE 获取进度
  │
  ▼
TaskQueue Worker（后台线程）：
  max_concurrent=2，每个 worker 循环从队列取任务
  │
  ▼
执行 publish_video():
  1. 通过 registry.get_platform(type) 获取平台实例
  2. 调用 platform.publish_video(**payload)（新逻辑）
    或 myUtils.postVideo 模块函数（旧逻辑，兼容）
  │
  ▼
平台实例（如 DouyinPlatform）：
  1. 从 cookiesFile/ 读取 cookie 恢复登录态
  2. 通过 CloakBrowser 启动隐身 Chromium
  3. 打开平台创作者中心/上传页面
  4. 填写标题、标签、描述、封面
  5. 上传视频文件（Playwright 填充文件 input）
  6. 提交发布（等待发布结果页面）
  7. 关闭浏览器（BasePlatform.close_browser）
  │
  ▼
更新 publish_details 记录（success/failed + publish_url）
  │
  ▼
SSE 推送状态变更 → 前端实时更新
```

## 4.2 浏览器自动化原理

### 4.2.1 CloakBrowser 隐身技术

```python
# _browser.py 核心
from cloakbrowser import launch_async

browser = await launch_async(
    headless=False,              # 有头模式（登录必须，发布可无头）
    args=["--start-maximized"],  # 最大化窗口
    humanize=True,               # 拟人化操作（贝塞尔鼠标轨迹、逐键打字）
    human_preset="default",      # 正常人速度
)
```

CloakBrowser 基于 Chromium，提供：
- **指纹伪装**：修改 WebGL、Canvas、AudioContext、Fonts 等指纹特征
- **自动化检测规避**：移除 `navigator.webdriver`、修正 `chrome.runtime` 等检测指标
- **拟人化操作**：鼠标轨迹贝塞尔曲线、随机延迟、逐键打字模拟

### 4.2.2 浏览器生命周期管理

```python
# 登录/有头模式 → 监听用户手动关闭浏览器
browser._is_close_by_code = False  # 标志位
# 用户手动关 → watchdog 自动 cancel 当前 task → 流程终止
# 发布成功 → platform.close_browser(browser, is_close_by_code=True)
#         → 先置标志再关闭，避免误判为失败
```

### 4.2.3 Cookie 登录体系

```
用户扫码登录（首次）：
  → 启动有头浏览器 → 打开登录页 → 用户扫码
  → 等待登录成功 → 保存 Playwright storage_state
  → 写入 cookiesFile/{filename}.json

cookie 重新导入（已登录）：
  → 用户粘贴 cookie 字符串
  → _parse_cookie_to_storage_state 解析 → 打开浏览器验证
  → sync_profile 获取用户信息 → 写入数据库

cookie 校验：
  → check_cookie(cookie_file) → 打开浏览器尝试访问创作者中心
  → 能正常访问返回 True，否则 False
```

## 4.3 任务队列系统

```python
# task_queue.py 核心设计
class TaskQueue:
    max_concurrent: int = 2     # 并发数
    queue: asyncio.Queue        # 任务队列
    running: dict[str, Task]    # 运行中任务
    completed: list[Task]       # 已完成任务

    # 后台线程运行 asyncio 事件循环
    def start(self):
        self._thread = threading.Thread(target=self._run_loop, daemon=True)
        self._loop = asyncio.new_event_loop()

    # 每个 worker 循环从队列取任务并执行
    async def _worker(self, name):
        while True:
            task = await self.queue.get()
            # 状态: QUEUED → RUNNING → SUCCESS/FAILED/CANCELLED
            # 更新数据库 + 通知 SSE 订阅者
            await self._execute(task)
```

**关键设计决策**：
- 重试逻辑已禁用（长耗时视频上传失败立即标记 FAILED，避免二次上传）
- 新 payload 透传逻辑：`task.payload` → `platform.publish_video(**payload)`
- 旧兼容逻辑：`myUtils.postVideo` 模块函数（硬编码平台映射）

## 4.4 数据库设计

```sql

tags            -- 标签定义
```

## 4.5 分片上传与断点续传

```
1. 前端创建 upload_sessions 记录（总大小、分片数、chunk_size）
2. 前端逐片上传，每片写入 upload_chunks 表
3. 上传完成后，服务端合并分片为完整文件
4. 创建 materials 记录，异步生成缩略图
5. 支持断点续传：查询已上传的分片，仅上传缺失分片
```

## 4.6 SSE 实时推送

```python
# SSE 订阅者模式
_sse_subscribers: list[queue.Queue] = []
_sse_lock = threading.Lock()

# 任务状态变更时通知所有订阅者
def _notify_subscribers(event):
    with _sse_lock:
        for sub in _sse_subscribers:
            sub.put(event)

# 前端通过 EventSource 或 fetch 流式读取
@app.route('/api/v2/events')
def sse_events():
    def event_stream():
        q = queue.Queue()
        with _sse_lock:
            _sse_subscribers.append(q)
        try:
            while True:
                data = q.get()
                yield f"data: {data}\n\n"
        finally:
            with _sse_lock:
                _sse_subscribers.remove(q)
    return Response(event_stream(), mimetype='text/event-stream')
```

## 4.8 MCP 服务原理

MCP（Model Context Protocol）服务对接 AI Agent：

```
LLM (Claude/ZCode) ←→ MCP Stdio/SSE ←→ MCP Server
                                        ↓
                                    HTTP Client
                                        ↓
                                Flask Backend (5409)
```

- 通过 Stdio 或 SSE 传输协议与 LLM 通信
- 提供 8 组工具：publish / accounts / drafts / materials / tasks / settings / changelog / publish_extra
- 可选 Token 鉴权，防止未授权访问
- 支持直接读取 SQLite（sql.js），绕过后端 API 直接查询

## 4.9 前端重点实现

### 4.9.1 平台表单动态生成

`config/platforms.js` 定义每个平台的表单配置（字段、校验、默认值），各平台发布页面根据配置动态渲染表单。平台专项组件（如 `douyin/TagSelect.vue`、`bilibili/CollectionSelect.vue`）按需加载。

### 4.9.2 批量发布流程

1. 选择多个账号（支持按标签过滤）
2. 配置各平台参数（封面、声明、定时等）
3. 调用 `POST /api/v2/publish` 创建批次
4. 前端轮询 SSE 获取发布进度
5. 任务完成后跳转到发布历史详情

### 4.9.3 自动保存

`composables/useAutoSave.js` 监听发布表单变化，定期自动保存到本地存储或草稿箱，防止页面刷新丢失数据。
