# Playwright 视觉基线（Visual Baseline / Visual Regression）说明

> 记录于 2026-08-21。本文档解释「视觉基线」是什么、怎么工作、成本与 ROI，
> 供后续决定是否引入时参考。尚未在仓库落地。

## 一句话

把页面/组件的**截图**当作测试断言：首次运行截图存为「基线」，之后每次运行重新截图做
**像素级对比**，不一致即失败 —— 用于抓住「功能正常但样式悄悄变了」的回归。

## 工作流程

```
第 1 次运行           之后每次运行
┌──────────┐        ┌──────────┐   ┌──────────┐
│ 真实浏览器  │        │ 真实浏览器  │   │ 基线截图   │
│ 渲染页面    │        │ 渲染页面    │   │ (repo 内) │
└────┬─────┘        └────┬─────┘   └────┬─────┘
     ▼                   ▼               ▼
  截图存为基线  ───────▶  像素对比  ────▶ 差异 > 阈值 → 失败
  (png 文件)              │
                          ▼
                人工判断：有意变更 → 一键更新基线
                          意外变更 → 修代码
```

关键点：基线是**人工审核过**的截图文件（惯例存放 `__snapshots__/xxx.spec.ts.png`），
与 vitest snapshot 同思路，只是从「文本」换成「像素」。

## 与现有测试的关系（互补，不替代）

| 维度 | 现有 vitest 组件测试 | Playwright 视觉基线 |
|---|---|---|
| 抓什么 | 行为 / 逻辑 / emit / 文案 | 样式 / 布局 / 间距 / 颜色 / 溢出 |
| 怎么断言 | DOM 结构 + 文本 | 整张截图像素对比 |
| 典型漏网 | —— | 「按钮 16px→14px」「hover 投影丢失」「8 个 stat 挤成一行」 |

对本仓库的针对性：F2 把 6 个 100~479 行的视图拆成子组件，行为测试全绿，但拆分过程中
**样式/结构悄悄变**（scoped class 失效、`<style>` 挪丢、层级塌掉）——DOM 断言抓不到，
只有像素对比能发现。

## 落地方式（参考）

```ts
// e2e/visual/account.spec.ts
import { test, expect } from '@playwright/test'

test('账号管理页视觉基线', async ({ page }) => {
  await page.goto('/#/account-management')
  await page.waitForLoadState('networkidle')
  await expect(page).toHaveScreenshot('account-management.png', {
    maxDiffPixelRatio: 0.01, // 允许 1% 像素差异
  })
})
```

- `@playwright/test` + 真实 Chromium（`playwright install chromium`）
- 起真实 dev/preview server，**mock 登录态与后端数据**（保证截图可复现）
- CI 用**固定 Docker 容器**跑（字体/抗锯齿跨平台不一致会误报）
- 有意改样式时 `npx playwright test --update-snapshots` 一键换基线

## 成本与坑

| 成本项 | 说明 |
|---|---|
| 基线初始化 | 首批截图人肉审核；数据必须 mock 稳定，否则每次跑都不一样 |
| 环境敏感 | 字体、显卡、窗口尺寸、动画时序会误报；必须容器化 + 固定 viewport + 禁用动画 |
| 维护负担 | 每次有意改样式都要更新基线，改动频率越高成本越高 |
| 运行慢 | 真浏览器 + 截图对比，全量分钟级，通常只跑 PR 级 |

## 对本项目 ROI 判断

- **当前阶段**：前端治理（F1/F2/F3）已收口进入稳定期，样式改动频率下降 → 上视觉基线主要是
  「防未来重构回归」，收益中等
- **值得上的时点**：① 下一轮大面积 UI 改动（重设计 / 换组件库 / 引入设计系统）；② 前端想彻底冻结
- **低成本替代**（防呆第一刀）：不做 Playwright 全家桶，只对 F2 拆过的 6 个视图做一次
  「拆分前后截图对比」人工核对，确认拆分未破坏视觉即可
